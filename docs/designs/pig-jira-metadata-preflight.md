# D1 Task: productize the read-only Jira metadata preflight

28 September 2026. Design candidate for a complete **metadata diagnostic suboutcome** on the path to S02a. It does not finish D1, select or save a project-board pair, inspect issue content, administer Pigboard callers, or close live Jira acceptance. The selected PIG connection design and six-outcome order remain unchanged.

## Outcome and boundary

An operator with the dedicated Scubapig service credential can run one local, noninteractive command to learn whether that exact identity can read the PIG project, Task/To Do mapping, and native board/filter/column metadata for board 2 and the correction fixture board 35. The command must name denied, malformed and unfinished reads instead of treating a partial list as an empty choice. A successful result means only those targeted metadata reads completed; it never says S02a can save a pair or that an issue is in a caller's audience. Remaining D1 work includes actual pair/filter behavior, designated issue and minimal-field membership reads, contextual permissions, issue links/statuses, and the separate caller-audience rule before S02b. This diagnostic is useful now as a reproducible connection check and later as S02a setup guidance. It is a focused implementation of the existing [D1 connection discovery](pig-jira-connection-discovery.md), whose standalone script is outside the product repository and has no regression tests.

## Contracts

1. Keep this command pilot-specific: fixed Scubapig cloud ID, dedicated service account ID, PIG project 10001, Task type 10009, boards 2/35 and QA filter 10034. These human-UI leads are checked against the service token; they are not inferred as proof. A future customer-wide chooser is S02a, not this diagnostic.
2. Accept `--client-id-file` and `--client-secret-file` as two distinct absolute paths. Each must be an owned, regular, nonsymlink mode-0600 file of 1–4096 bytes under an owned mode-0700 directory. Open with `O_NOFOLLOW`; compare the opened file's device/inode, owner, mode and size to the pre-open stat, read with a 4096-byte cap, and recheck the parent directory's identity before using either value. Allow one optional trailing LF and otherwise require a nonempty printable ASCII value without whitespace or controls. Refuse unsafe files before any network request. Do not accept credential values in arguments, environment variables, stdin or prompts, set them in `process.env`, spawn a child with them, or log them. Read both only for this invocation; no saved copy. Send them only to Atlassian's token endpoint, use the bearer only for the fixed Jira gateway, reject redirects, and never log raw bearer, secret, filter JQL, issue data or raw HTTP bodies. Issue no Jira write or issue read. The credential stays out of the repository and examples.
3. First call `/myself` and require an exact match to the dedicated service account before any project or board request. Then perform the reviewed targeted read route set: direct project, first-page PIG project search, project statuses, first-page PIG board list, each board, each configuration, each static project association, and each board's actual filter. Require the direct project and project search to match PIG `10001`, and the board list and direct boards to match both known IDs `2` and `35`. A missing known target or unfinished list is incomplete, even if other targets appear. Do not assume board 2 uses filter 10034. Require board 35's configuration to reference QA filter `10034` and require the fetched filter to match the human-observed PIG-only query `project = PIG ORDER BY Rank ASC` after case and whitespace normalization. A fixture mismatch is incomplete, with only a local reason reported; never print raw JQL. For `/board/{id}/project/full`, accept a valid array or complete page; an empty result means `static_association_not_established`, not a denied read or an invalid pair. An unfinished page means incomplete. Do not invent pagination parameters for that route. The diagnostic reports static association separately from actual pair validity, which remains unproved until later filter/membership checks.
4. Report text and machine-readable JSON with the same stable local route labels, HTTP status and local reason enum, selected native IDs and names needed for diagnosis, targeted metadata checks and explicit omitted evidence. Validate response shapes and the unique Task/To Do status mapped to one To Do board column. Cap response bytes, array items and displayed strings; reject unsafe controls or overlong names instead of echoing them. Never pass through vendor error text, headers, raw JQL or unrelated project/board names. Report 401 authentication, 403 permission, 404/not-visible, malformed JSON/shape, timeout, unfinished page, missing known target, fixture mismatch and mismatched identity distinctly. A missing credential or wrong identity stops the sequence; any incomplete required read returns a nonzero exit. Exit zero means all targeted route bodies and known-target predicates were validated, even if static association was not established; it explicitly leaves pair validity, issue membership, caller audience and other D1 work unproved.
5. A completed metadata diagnostic is not an authorization grant, accepted board pair, caller-audience proof or live acceptance. It cannot mutate selection or move the approved project scope. If board configuration is denied, name that route and stop short of S02a readiness; do not grant global Jira administration as a workaround.

## Delivery and verification

Target one repository PR with a small command/module, tests with fixed fake Atlassian responses, a short operator guide, package entry and queue link. Reuse the existing external script's route logic only after inspecting it; do not copy its environment-secret or unbounded-output behavior. Tests cover protected-file refusal before network, route/body bounds, known project and board target/fixture drift, static-association array/complete-page/empty/unfinished cases, identity mismatch, denied routes and no false pair success. Expected 5–8 changed files and 8–12 human hours including docs, tests and PR preparation; inventory again in the Story and plan. Local fake API tests establish only local behavior, while a later service-token run is a separate live D1 gate. If review finds that this diagnostic requires new authority, a different API contract or more than two days, keep it a Task and do not code it.

## Author seven-principle assessment

1. **Intuitive:** one command gives a plain diagnostic of the fixed PIG setup; it does not ask a pilot operator to guess status or filter IDs. A general selector comes later.
2. **Discoverable:** help and the guide name credential setup, successful metadata proof and recovery for denied or incomplete routes; JSON gives agents explicit fields.
3. **Delightful experience:** one run replaces repeated manual Jira API calls. A protected credential file adds setup but avoids accidental shell-history disclosure.
4. **Token saver:** selected IDs, route states and omitted evidence lead; the tool does not dump raw Jira bodies or every unrelated choice.
5. **Secure:** identity-first reads, fixed hosts, no redirects, protected secret input and no issue/write route bound disclosure and effects. A read scope does not replace effective Jira permissions.
6. **Agents are equal:** humans get text and recovery guidance; an operator agent gets the same result in JSON and a noninteractive exit code. Neither receives broader project authority.
7. **Dependable:** unknown, denied, unfinished, malformed and absent static association are distinct; exit zero never claims D1 completion, S02a pair save or caller-audience proof.
