# Implement the PIG Jira metadata check

28 September 2026. This plan implements the [metadata diagnostic Story](../stories/pig-jira-metadata-preflight.md) under the [reviewed D1 design](../designs/pig-jira-metadata-preflight.md). It is one pilot-specific, read-only technical outcome before S02a. It does not save a connection, validate the project-board pair, inspect an issue, grant access, or accept D1 live evidence. The existing standalone discovery probe informs the route list, but its environment-secret input and unbounded vendor output are not copied.

## Current code and change boundary

The repository has Node 20 ESM scripts and `node --test`; no Jira adapter exists. `src/hosted/private-caller-client.js` shows the owned mode-0600 file and mode-0700 parent checks. Use that pattern for two OAuth values without coupling the diagnostic to the private Fly route. Add only a Jira metadata module, CLI, tests, operator guide, package command, README entry, Story/design/review/plan records and delivery-queue link. The proposed PR has 10–11 changed files, under the 20-file cap, and 8–12 human hours including checks and PR preparation. If implementation grows beyond the size limit, split a complete outcome before committing.

## Contract and implementation steps

1. Add `src/jira/pig-metadata-preflight.js` with fixed Scubapig cloud ID, service account ID, PIG project/type IDs, board IDs 2/35, and QA filter ID 10034. Inject filesystem and fetch operations for tests, but expose no runtime override for hosts, account, project or boards. Use only the standard Node APIs.
2. Read two distinct absolute credential-file paths. For each parent, `lstat` the directory and require ownership by the current UID, exact mode 0700 and a real directory; record device, inode and real path. `lstat` each leaf and require a regular nonsymlink owned 0600 file of 1–4096 bytes. Open with `O_RDONLY | O_NOFOLLOW`, compare `fstat` device/inode, owner, mode and size, read at most 4097 bytes, compare count to the opened size, close, then recheck each parent identity. Reject the file or parent if it changed. Strip at most one final LF; reject empty, whitespace, controls or nonprintable/non-ASCII values. Read both safely before requesting a token. Never put values in a child environment or logs.
3. POST the OAuth client credentials to `https://auth.atlassian.com/oauth/token` with `grant_type=client_credentials`; accept a bounded, valid JSON token only. Set `redirect: "error"`, a 15-second per-request deadline, a 256-KiB response-body cap and no automatic retry. Send the bearer only to `https://api.atlassian.com/ex/jira/<fixed-cloud-id>`. Never accept a caller URL or follow a redirect. No request targets issue, comment, transition or write routes.
4. GET `/rest/api/3/myself` and require the exact dedicated account ID before any project or board read. If token or identity proof fails, return only a local reason and stop. Then read direct project, first-page PIG project search, project statuses, first-page PIG board list, both boards, both configurations, both static project associations, and each configuration's actual filter. A missing filter ID records `not_attempted` for that filter read rather than guessing one.
5. Validate each response from a bounded parsed object. Require the known PIG project in direct and complete search results, unique Task/To Do status ID, both known boards in a complete list and matching direct boards, each board's filter ID and nonempty columns, and one placement of the Task/To Do status in the native To Do column. Require board 35's filter ID 10034 and its actual JQL to normalize to the observed PIG-only query; do not print JQL. Board 2's actual filter is read but is not assumed to use 10034 or declared a valid pair by this command. Accept `/board/{id}/project/full` as an array or a complete page; empty means static association not established and does not fail the metadata route. An unfinished page is incomplete. Do not invent pagination parameters for this route.
6. Build each result from local labels, an HTTP status, local reason enum and selected validated IDs/names only. Permit at most 50 entries on target lists, at most 20 columns and 20 statuses per column, at most 120 characters per displayed name, no unsafe controls or line separators, and a 64-KiB total rendered output cap. Do not echo vendor headers, error strings, raw bodies, raw JQL or unrelated names. Include `schemaVersion`, `status`, `routes`, `omissions` and `nextAction` in JSON; text renders the same meaning. `status: "metadata_complete"` and exit 0 require all targeted route predicates. Wrong identity, denied or missing data, malformed body, timeout, missing known target, fixture mismatch and unfinished page are distinct `metadata_incomplete` reasons with exit 1; invalid invocation or unsafe local credential has exit 2 before network. Static association absence remains separate. Always list pair validity, issue membership and caller audience as unproved.
7. Add `scripts/check-pig-jira-metadata.mjs` with `--client-id-file`, `--client-secret-file`, optional `--format text|json`, and `--help`. Duplicate/unknown flags or unsafe values fail with usage help but no secret echo. Add `jira:metadata` to `package.json`. Document safe file setup, ordinary output, exact evidence limit, denied/partial recovery and the separate live service-credential run in `docs/pig-jira-metadata-preflight.md`. State the 19-granular-read-scope union recorded for the targeted routes in the D1 service-read evidence, especially `read:board-scope.admin:jira-software` plus `read:project:jira` for board configuration and static association. Explain that an OAuth read scope does not grant effective Jira/board access or justify global Jira administration; a 403 calls for checking that route's scope, filter sharing and PIG-local permission before retrying. Check current Atlassian scope documentation when writing the guide. Add a concise README entry with the command, guide link and live-credential/evidence limit. Link the Story and its distinct live gate from the active delivery queue.

## Verification and rollout

Test fake HTTP responses for complete metadata, wrong service identity before project reads, missing targets, board-35 filter drift, denied configuration, malformed/oversized bodies, timeout, unfinished lists, static-association array/complete-page/empty/unfinished shapes, output sanitization and protected-file refusal before network. Record every fake-fetch request and assert that ID/secret reach only `auth.atlassian.com`, bearer reaches only the fixed `api.atlassian.com` cloud path, a 3xx response has no follow-up request, and no issue or write route is attempted. Run the narrow test file first, then `npm test` and `git diff --check`. The author separately reviews the final diff against all seven principles and checks README, guide and help examples. Commit, obtain two fresh Sol exact-commit reviews with complete coverage and second sweeps, fix/recommit/re-review real findings, then open a PR and verify current-head hosted checks. A live run requires the separately created dedicated service OAuth credential; local fake tests and a merged command do not establish live Jira access or S02a readiness.

## Author seven-principle assessment

1. **Intuitive:** a single named command checks the pilot target and states what it proved; it avoids manual API calls. The later customer chooser remains separate.
2. **Discoverable:** help and guide show file setup, text/JSON use, success limits and route-specific recovery; no user must infer a failure from a blank list.
3. **Delightful experience:** one run replaces a series of manual probes. Protected file setup is an up-front cost for keeping secrets out of shell history.
4. **Token saver:** only target facts and omissions appear, while raw Jira bodies and unrelated names stay out of output. Bounded JSON lets an agent use one result.
5. **Secure:** fixed read destinations, identity-first checks, protected files, redirect refusal and no issue/write routes limit exposure. This does not prove caller-level authorization.
6. **Agents are equal:** text guides a human and the same evidence has stable JSON and exit codes for an agent without prompts.
7. **Dependable:** wrong identity, denied, incomplete, malformed and absent static association are distinct. Exit zero proves targeted metadata only, and live access remains a separate gate.
