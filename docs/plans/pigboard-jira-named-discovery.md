## Usable outcome and exact request contract

One noninteractive `npm run --silent jira:choices -- --token-file /absolute/private/caller.token [--format text|json]` command calls private `GET /v1/jira/choices` with the same protected 0600 file and pinned Flycast target rules as `caller:me`. There is no site/project/board argument or interactive prompt. Default text prints `Pigboard Jira choices: complete`, `PIG — Pigboard (10001)`, each returned board as `name (id, type)`, then a short `Not yet: pair selection, board eligibility, issue access` and next step. JSON carries the exact validated server fields, so an agent can consume stable IDs without parsing text. Exit0 is complete, exit1 is denied/unavailable/uncertain/unverified, exit2 is invalid usage. `--help` includes command, private-route, protected-file and recovery examples. No browser UI or Postman dependency is added.

The Story is accepted when both current owner and agent receive the same complete approved names/IDs; invalid/revoked/ungranted callers cause no Jira request or disclosure; revoke or grant loss during fetch withholds names; incomplete provider reads never appear complete; and human help plus agent JSON give omissions and recovery. The host keeps health/me and the operator diagnostic working, and adds no write or schema change. These criteria are mirrored in the external groomed Story and remain reviewable in the repository plan.

Request: GET, exact route, one `Authorization: Bearer pb1_...`, `Accept: application/json`, no body/query; any other method/path stays 404. Successful HTTP200 JSON is `{schemaVersion:1,status:"complete",site:"scubapig.atlassian.net",projects:[{id:"10001",key:"PIG",name,boards:[{id,name,type}]}],omissions:["pair_selection","board_filter_eligibility","issue_access"],nextAction}`. Boards sort by numeric native ID. No board match is a valid empty `boards:[]` only after complete pagination. HTTP401 `denied`, 503 `unavailable`, 502 `uncertain` contain `schemaVersion,status,reason,omissions,nextAction` and no names/IDs. The client independently accepts only these exact schemas, fixed site and approved project ID/key, bounded safe names/types, unique IDs, sorted boards, allowlisted reason/omission codes and `cache-control:no-store`; otherwise it reports local `unverified` with no provider text or names. Cap both host and client JSON at64 KiB and at most200 boards; over-limit is `uncertain`/`unverified` without partial output.

| Trigger | HTTP / result | Reason and recovery |
| --- | --- | --- |
| Missing, malformed, unissued or revoked bearer, or no current `connection_admin` | 401 `denied` | `invalid_credential` or `grant_denied`; check own current grant with the owner, no Jira request and no names |
| First or final current-grant check cannot complete | 503 `unavailable` | `authority_unverified`; inspect private host/Neon and retry read, no names |
| Jira client secret missing/invalid, OAuth/access refused | 503 `unavailable` | `jira_unavailable`; owner checks staged secret and service access, no names |
| Exact account/cloud target mismatches, approved PIG identity absent/ambiguous, malformed/inconsistent/unfinished/capped pages, redirect/oversize/provider timeout | 502 `uncertain` | `metadata_unverified`; owner inspects safe metadata diagnostic/provider state, then caller retries read; no names |
| Client unsafe token file, transport deadline, response/schema/header mismatch | local `unverified` | `request_unverified`; correct local custody/private route or retry, no names |

Do not reflect provider HTTP status/body or client IDs in public errors. `nextAction` is a fixed bounded string selected from local reason code; `omissions` includes `approved_choices` for all non-complete server results, and complete result carries the three deferred capabilities. The client never treats a non-200 or malformed 200 as empty success. Unknown provider completion produces no cached or partial list; this read has no write to reconcile.

## Code sequence and failure guards

1. Add one nonsecret immutable approved manifest, `config/pigboard-approved-jira.json`, with the exact Scubapig site, cloud ID, service account ID, project10001/key PIG and bounded page/board limits. Validate at host startup. A manifest mismatch or missing managed secret makes discovery unavailable but leaves `/health` and `/v1/authority/me` usable. No wider admin API or mutable scope table is introduced. Package that manifest and `src/jira` in the production image.
2. Add `src/jira/approved-discovery.js` with a typed read-only provider function, injected fetch/clock for tests. Read managed host values `PIGBOARD_JIRA_CLIENT_ID`/`PIGBOARD_JIRA_CLIENT_SECRET` only inside this module; never log or return them. OAuth client-credentials POST uses the exact scoped token endpoint, then `GET /rest/api/3/myself` verifies the expected account on the pinned cloud URL. Project `search?keys=PIG` and board `?projectKeyOrId=10001` use fixed query values, no caller input. Each page validates `values,startAt,maxResults,total,isLast`, checks advancing offsets and stable totals, and visits every page up to4 pages/200 candidates. Require a single exact native project ID/key match. Filter normalized results against the manifest; never return unrelated names. Project/board names must be nonempty, <=120 Unicode characters, without controls/format/separators; IDs numeric, board types bounded. Duplicate IDs, unexpected shapes or incomplete traversal fail as `metadata_unverified`. Preserve the existing operator `jira:metadata` script unchanged.
3. Extend `src/hosted/health-server.js` with the exact GET route and injectable `inspectSelf`/`discoverChoices`. Parse bearer using the existing single-header rule. First `inspectOwnGrant` result must be `ok`, `team:pilot`, `principal.kind` human/agent and include `connection_admin`. No OAuth call precedes it. Buffer the complete sanitized provider result; then call `inspectOwnGrant` fresh with the same bearer. Require **the same `principal.id` and `principal.kind`**, team pilot and current `connection_admin`; a changed generation alone is acceptable after that fresh decision. Final `denied` discards buffer and returns401; final unavailable discards buffer and returns503. No long Neon lock, SQL DML, new privilege function, pair store or effect guard. A revoke committed after the final check cannot retract already sent bytes.
4. Use one absolute 90-second server deadline covering both authority checks, OAuth, all pages and cleanup. A route-local `AbortController` fires on that deadline or an unfinished response `close`; remove its timer/listener on all exits. Its signal goes to every Jira fetch/body reader and to a **small optional signal seam** in `openPinnedRuntimeClient`; `/me` calls it without a signal and keeps its present defaults. In the Neon helper, check pre-abort before creating/connecting a client, race connect and root-diagnostic query against the signal, and destroy the actual owned PostgreSQL stream on abort. Keep the abort listener through the returned connection lifetime; the returned `close()` removes it and performs bounded close. Track the original connect/query promises: if either settles late after abort, destroy/close that same client again before releasing the finalizer, so a late connection is never handed to the grant query or leaked. In the route's `inspectOwnGrant` `openConnection` seam, pass that signal and remaining time through existing timeout overrides, then wrap the returned connection's grant `client.query` in a signal race while retaining its abort-aware `close()`. Thus the one subsequent grant query also obeys the absolute deadline without changing `authority-self.js` or `/me`. The route checks signal/deadline again after each awaited stage, including final grant, and never sends buffered names after expiry/disconnect. A one-second bounded database close may finish after deadline, but no response is sent and the 95-second client budget includes it. Keep global 30-second connection and 5-second query maxima unchanged. Jira requests get 15 seconds or remaining budget, including bounded body read; release fetch readers/timers in `finally`. A cold Neon/Jira combination may return bounded unavailable/uncertain; verify rather than increasing timeouts solely to make a failure green. No automatic provider retry or disk cache.
5. Add discovery-specific request/strict-response validation to `src/hosted/private-caller-client.js` using its existing protected-file reader and pinned private target; keep `/me` behavior unchanged. Add `scripts/discover-pigboard-jira.mjs` and the `jira:choices` package script with text and JSON output. No bearer in args, logs or errors. Unverified transport cannot be mistaken for a server denial.
6. Extend the production-image checker to verify the built image contains/imports the approved manifest and Jira module and that the new private route without a bearer denies without secrets, as well as current build/start/health/owned cleanup. Use synthetic safe values only. Do not make `/health` contact Jira or Neon. Update corresponding checker regression.

## Author assessment of the seven principles

1. **Intuitive:** command shows project and board names with IDs and type, while saying selection is later. An operator still handles private peer setup; that pilot prerequisite is documented.
2. **Discoverable:** README and guide link to one command/help, structured JSON and fixed recovery reasons. No unimplemented save command is suggested.
3. **Delightful experience:** one request gives the complete approved list; no ID guessing or repeated setup. Cold infrastructure may require a bounded retry rather than hiding uncertainty.
4. **Token saver:** compact choices carry names, IDs, types and omissions; no raw Jira payload or JQL. The caller can request JSON without extra discovery calls.
5. **Secure:** exact host secret custody, immutable PIG manifest, identity proof, before/after current same-principal grant, private pin and no partial metadata protect disclosure. Board eligibility remains explicitly unproved.
6. **Agents are equal:** owner and agent use the same route and complete data with their own bearer; JSON and noninteractive exits serve the agent directly. Neither may administer scope or secrets.
7. **Dependable:** complete, denied, unavailable, uncertain and local unverified remain distinct; page gaps and revoke during fetch disclose nothing. A response sent before a later revoke cannot be withdrawn, and the guide states that limit.
